# Turn Notifications

On the `fmind/dot` workstation, notifications mean it is your turn: the main session is idle or needs an answer. Restart open harnesses after changing notification configuration.

- **Claude**: `Notification` hooks select `idle_prompt` for “Your turn” and actionable permission/question events for “Needs your input”. The idle alert waits about 60 seconds without typing. No `Stop` notifier is managed because those hooks run before continuation decisions. Informational notifications and background-agent completion do not trigger the managed notifier.
- **Copilot**: native attention notifications are enabled; no `Stop` / `agentStop` desktop hooks are managed, avoiding premature and duplicate alerts. Native alerts depend on the host's focus detection and terminal/OS support.
- **Antigravity**: the managed `Stop` notifier requires `fullyIdle: true`, including through the `antigravity` alias; native input notifications remain enabled and (since 1.3.1) alert on pending agent questions as well as tool permission prompts.
- **OpenCode**: native desktop attention alerts exclude child sessions. Sounds are disabled because child completion also plays them.
- **Delivery uses native OS notifiers**: Linux uses `notify-send` (`libnotify-bin`, a README prerequisite); macOS uses the built-in `osascript` notification command. With `agent.notify.sound` (default on), macOS plays the `Glass` system sound; Linux suppresses the server's sound and plays dot's generated chime (`~/.cache/dot/notify.wav`) with `pw-play` or `paplay`, because ChromeOS `notificationd` plays none. On ChromeOS, a managed user D-Bus activation file starts the bundled Crostini `notificationd` bridge on demand. Headless sessions without a notification service skip delivery; operating-system notification settings still control visible banners.
- **Content stays short**: managed notification titles show a status icon (✅ your turn, ⏳ needs input), the harness, and the project (limited to 80 characters). Inside Zellij, one `zellij action list-panes` call adds the session and tab (`agent.notify.tab`) and the pane title the harness sets (`agent.notify.title`), such as Claude Code's session topic without its status glyph; both default on and replace the status words in the body; outside Zellij, or when the lookup fails, the body reads “Your turn” or “Needs your input”. macOS shows the pane title as the subtitle. The title summarizes the conversation, so turn it off where banners are visible to others. Notifications have no click actions and never read prompt or transcript content. Native notifications use the harness's own presentation.
- **Failures never fail the turn**: a failed notification writes one stderr line and exits 0, so it never fails the agent turn.
- **Brain session context** (not a notification): only when `~/fmind/brain/settings/hooks/session-context.py` exists, apply adds it as a `SessionStart` hook with a 30-second timeout to Claude (no matcher); removing the brain leaves the entry for the host to drop. For agy, when `~/fmind/brain/settings/hooks/agy-context.py` exists, apply adds the `brain-context` named hook on `SessionStart` (30-second timeout), which injects the context once per conversation as a persistent `systemMessage`; [agy](../../agy/references/agy/GUIDE.md) explains why `PreInvocation` is unsuitable.
