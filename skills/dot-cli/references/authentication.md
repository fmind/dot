# Workstation Authentication

GitHub, Workspace, GCP, and Colab login check current authentication and scopes before opening a browser; skipping requires usable credentials that cover the requested scopes. `dot login all` runs `setup github`, GCP and ADC (Workspace setup lists and enables APIs through gcloud), Workspace setup (only when `GWS_PROJECT` or `auth.workspace.project` names a project), then Workspace login, skipping ready steps and stopping on failure. GitHub login uses the web flow with gh's configured `git_protocol`, so only gh's SSH-key choice and its Enter-to-open prompt remain. gws only prints its OAuth URL, so Dot opens it through Python `webbrowser` (honoring `$BROWSER`) when a graphical session exists; the printed URL stays the fallback. `--force` repeats authentication; `--dry-run` previews possible commands without executing probes. Unknown status fails with recovery guidance instead of starting authentication. Colab skips authorization when ADC already grants the configured scopes, then verifies session access. Repair or remove environment-token overrides when they prevent OAuth updates. GCP checks CLI and ADC credentials separately without asserting one identity and re-authenticates only the missing one: `gcloud auth login` for the CLI, `gcloud auth application-default login --scopes=<auth.gcp.adc_scopes>` for ADC. Requesting a token for the configured scopes proves the ADC grant, because Google rejects scopes outside it; Workspace setup reads enabled APIs from `gws auth status` for its configured project (falling back to `gcloud services list` for another project), enables only missing configured APIs, and skips OAuth client setup when the project already has a readable client configuration. Failed probes print no captured tokens or provider payloads, and Dot keeps no credential cache.

For a read-only cross-provider sweep of login state, expiry, scope gaps, and re-login commands (including Hugging Face, Kaggle, AWS, Databricks, and Atlassian), use [auth-status](../../auth-status/SKILL.md); this guide owns the login policy it reports against.

Workspace project selection uses the setup argument, then `GWS_PROJECT`, then `auth.workspace.project`. GitHub login always targets github.com. Inspect policy with `dot config show` and edit it with `dot config edit`: `auth.github.scopes`, `auth.github.remove_scopes`, `auth.workspace.scopes`, `auth.workspace.apis`, `auth.gcp.adc_scopes`, and `auth.probe_timeout_seconds`. Maps merge with defaults; configured lists replace the entire default list.

The default policy covers repository, publishing, document, mail, calendar, contact, Chat, Meet, Forms, Tasks, Drive Activity, Cloud Support, and Apps Script workflows, including Gmail settings/filter and Chat read-state management, plus read-only Analytics, Search Console, and YouTube reporting. gws replaces its whole grant on login, so a custom `auth.workspace.scopes` list must keep the scopes brain sensors borrow. The policy excludes GitHub repository/package deletion scopes and permits SSH key creation without key administration. Gmail uses `gmail.modify`, which excludes immediate permanent message deletion; full Drive and other editing scopes can still permit destructive operations. OAuth capability does not authorize deletion or contacting others, including opening Cloud Support cases. GCP permissions remain controlled by IAM. Applying configuration does not change issued tokens: authenticate again for new scopes and use `dot setup github` to remove excluded grants. Personal Google accounts need a Workspace policy without `directory.readonly`. `dot login github`, `dot setup github`, and `dot doctor --deep` warn when gh stored the token in plaintext `hosts.yml` because no keyring accepted it; unlock the system keyring, run `gh auth logout`, then `dot setup github`. On ChromeOS Crostini, GitHub login copies the one-time code through X11 (`WAYLAND_DISPLAY` cleared) because `wl-copy` never returns under Sommelier.

## Colab ADC

ADC replaces its whole grant on every login, so `auth.gcp.adc_scopes` owns every ADC consumer's scope: gcloud's defaults (`openid`, `userinfo.email`, `cloud-platform`, `sqlservice.login`) plus `colaboratory`. `dot login gcp` and `dot login colab` request the same list, so neither drops the other's scopes. `dot login colab` refuses a list without the Colab scopes, then authorizes only when the scoped ADC refresh fails (or with `--force`) and verifies session access:

```bash
gcloud auth application-default print-access-token --scopes=<auth.gcp.adc_scopes>  # readiness probe
gcloud auth application-default login --scopes=<auth.gcp.adc_scopes>               # only when needed
colab --auth=adc sessions
```

`auth.probe_timeout_seconds` bounds both checks. Session access alone does not prove the full scope grant, so the scoped refresh decides whether to skip authorization. `--dry-run` prints the login and session commands without probing. Session inspection allocates no VM. An empty listing is accepted only without authentication failure diagnostics, since Colab can exit successfully after an ADC failure. Unknown failures require native inspection before retrying.

Colab uses the shared ADC file, so this login replaces its existing user credentials and scope grant without changing the gcloud CLI account. `GOOGLE_APPLICATION_CREDENTIALS` takes precedence; repair or unset it before changing stored ADC. If a native login replaces ADC without the Colab scope (such as `gcloud auth login --update-adc`), run `dot login colab` again.

## Customer overrides and isolation

**Customer accounts:** Hugging Face's nonempty `HF_TOKEN` overrides its token file; set `HF_TOKEN_PATH` before starting Python when selecting a separate file. Kaggle's personal access-token file takes precedence over legacy keys and OAuth; `KAGGLE_CONFIG_DIR` does **not** redirect it. Select `KAGGLE_API_TOKEN` explicitly for customer work. OpenCode's saved login can override an environment key; use project `provider.openrouter.options.apiKey` with an environment/file reference, or isolate its login with `XDG_DATA_HOME`. Empty environment variables are not a universal way to disable native credentials. See the [HF environment reference](https://huggingface.co/docs/huggingface_hub/en/package_reference/environment_variables), [Kaggle token resolver](https://github.com/Kaggle/kaggle-sdk-python/blob/main/kagglesdk/kaggle_env.py), and [OpenCode providers](https://opencode.ai/docs/providers/).

Kaggle 2.2.4 tries legacy keys and OAuth if an access token is invalid; the scoped helper does not change native authentication behavior. For strict customer separation, use a separate OS account/container or a dedicated home and credential configuration without personal logins. A missing customer HF token file yields no saved token, but may permit anonymous operations; it does not guarantee an authentication error for public resources.

## Scoped credentials

`dot secret run NAME -- COMMAND ...` uses an existing `NAME` environment value first, then `~/.config/dot/secrets/NAME`. An explicitly empty value, missing/insecure file, or malformed credential fails before the command starts. It never retries with personal credentials after an authentication failure. This helper is an explicit opt-in to personal credentials: use the ordinary command for customer profiles and ADC. Child processes inherit the selected key and the rest of the existing environment; the parent shell does not gain the key. This is credential scoping, not a sandbox or an environment scrubber. Arguments, terminal input/output, and exit status are preserved. Nest the helper if a command needs multiple keys. Shell startup exports no API keys; native HF, Kaggle, and OpenCode logins are seeded only when absent. See [secret setup and migration](https://github.com/fmind/dot#secret-management).

The managed scoped keys are `ANTIGRAVITY_SDK_API_KEY`, `VERTEX_API_KEY`, `STITCH_ACCESS_TOKEN`, and `OPENROUTER_MANAGEMENT_KEY` (read-only OpenRouter usage reporting). `VERTEX_API_KEY` replaces the personal AI Studio credential; SDKs must read it explicitly. Prefer ADC and never map it into globally auto-discovered Google key variables. See [GCP Agent Platform defaults and key fallback](../../model-providers/references/gcp-agent-platform.md). PyPI packages publish through [Trusted Publishing](https://docs.pypi.org/trusted-publishers/) in CI; `dot secret run` rejects `UV_PUBLISH_TOKEN` so no long-lived personal upload token returns. Delete any leftover `UV_PUBLISH_TOKEN` or `JULES_API_KEY` seed under `~/.config/dot/secrets/` by hand. Use native `uv publish` with explicitly selected credentials for other registries.
