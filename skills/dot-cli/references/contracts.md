# Dot Contracts

Configuration precedence is explicit `--config`, then `DOT_CONFIG_PATH`, then `~/.config/dot.yaml`. A missing default uses built-in defaults; an explicit missing file fails. Workstation policy lives under `auth`, `cache`, and `prune`; `dot config show` exposes the complete defaults. Scope lists replace defaults, so `dot config init` writes them as comments for later releases to keep updating; native tools own credentials. Configuration uses `schema_version: 3` and positive finite numeric seconds in `timeout_seconds`, and `probe_timeout_seconds`. Unknown keys are rejected. Help and config repair commands remain available with malformed configuration; chezmoi-managed edits go through their source, including paths with symlinks or `..`.

Requested data goes to stdout; progress and errors go to stderr. Exit codes are 0 for success, 1 for an operational failure or incomplete result, 2 for usage errors (including unknown agent names), and 130 for interruption. Every JSON report has a versioned `schema` envelope; failed operations never become an empty success. Notification hooks do not load unrelated configuration; they always exit 0 and report a failure as one stderr line.

The active `sessions/v3` store keeps one private bundle per agent session, `<agent>/<session_id>.jsonl`: a manifest line (schema 3) with provenance, counts, source signature, and usage, then the normalized records. Sync serializes writers with an owner-only `.write.lock`, checks that no competing capture replaced the observed generation, and publishes the whole file atomically. It retains the archived copy when records disappear or a matching message shrinks. When only a provider token measurement or known cost would become unavailable, it publishes a transcript that does not shrink with the archived usage, records the measuring parser in `usage_parser_version`, counts the session as retained, and retries it on the next sync. Sources that change during parsing fail without publication and retry. Malformed JSONL and usage extraction failures report errors and never replace an archived measurement; the transcript still publishes under the same non-shrink rules, with the archived usage or, for a first capture, without usage, and retries. Missing measurements remain unavailable; explicit zero counters stay distinct from unknown usage, and independently reported cost remains available without claiming complete token pricing. Sync writes parser 10 and reads parser 3 through 10 bundles; earlier parsers have the session status `legacy` until sync recaptures their sources. Usage accounting separately flags parsers 3 through 6, plus parser 7 for Grok, as legacy, judged by the parser that measured the usage; a newer parser alone does not invalidate other harnesses' parser 7 measurements. Parser 7 adds usage-presence accounting; an unchanged source can repair an older fabricated zero during recapture only when actual tokens and known cost are preserved. Parser 8 preserves Grok aggregate costs independently of per-model cost details. Parser 9 treats an explicitly incomplete Grok ledger as unavailable usage while retaining complete transcript text; malformed metrics still fail. Parser 10 records Claude 1-hour cache writes and Codex per-response usage including compaction requests, treats Claude's `hasUnknownModelCost` as unknown cost, marks subagent transcripts as sidechains of their parent session (`sidechain`, `parent_session_id`), and skips Claude workflow journals. Deeply nested JSON is malformed input, and an unexpandable `~user` project path is a usage error. Parser 7 accounting remains accepted for other harnesses, including explicitly measured zero usage. Previously archived measurements remain retained when an incomplete source cannot safely replace them. Legacy zero-token measurements remain unpriced when the old archive cannot prove that counters were observed; recognized Claude synthetic responses stay known zero. Recorded cost remains independent. Claude user text blocks and strict provider metric validation remain supported. A store that exists only as `sessions/v2` requires migration with Dot 7.0.4 and is never modified; earlier stores and standalone usage files are never read. Unsupported bundles fail queries and their capture without replacing them; sync can still capture other sessions.
