# Dot Contracts

Configuration precedence is explicit `--config`, then `DOT_CONFIG_PATH`, then `~/.config/dot.yaml`. A missing default uses built-in defaults; an explicit missing file fails. Workstation policy lives under `auth`, `cache`, and `prune`; `privacy.allowed_tokens` lists already-public names the fmind/dot privacy check accepts on this machine, so the repository never names them; `dot config show` exposes the complete defaults. Scope lists replace defaults, so override only the lists you change; native tools own credentials. Configuration uses `schema_version: 3`; timeouts, concurrency, and secret permissions are fixed in code. Unknown keys, including removed settings and `agent.sources` entries for retired or misspelled agents, fail with their key path; delete them with `dot config edit`. Help and config repair commands remain available with malformed configuration.

Requested data goes to stdout; progress, prompts, and errors go to stderr. Exit codes are 0 for success, 1 for an operational failure or incomplete result, 2 for usage errors (including unknown agent names), and 130 for interruption. Interruption stops launched subprocesses, including cancellation during startup. Every JSON report has a versioned `schema` envelope; failed operations never become an empty success. `orphan` and `secret` never read configuration; notification hooks read only `agent.notify` and fall back to its defaults, with one stderr line, when configuration is missing or invalid. Hooks always exit 0 and report a failure as one stderr line. Durations such as `7d` and `24h` work across date-filtered commands; zero-length durations such as `0d` exit 2; [daily workflows](daily-workflows.md) owns date boundaries.

## JSON selectors

Check the exit status: a failure before report construction may produce no JSON, and warnings stay on stderr. JSON is indented on a terminal and compact (no whitespace) when piped; parse it rather than matching text.

Diagnostics use the `dot.diagnostics/v1` envelope; agent doctor details carry `agent`, `hooks`, `source`, `last_sync`, `sync_failures`, `sync_retained`, `archive`, `sessions`, `healthy`, `next`, `discovery` (`ok`, or `broken:` with `persona` or `skills` when the deployed host files miss the shared persona or skills catalog), and `note` (an advisory that never affects `healthy`, such as the caller's environment lacking `OPENCODE_DISABLE_CLAUDE_CODE_SKILLS=1`, so an OpenCode launched from it loads the catalog twice). Native cache/provider output keeps its native format. Stats rows count model `requests` (`null` once agy or Grok contributes, since their counters track prompts or completed turns); `retained_usage_sessions` counts sessions whose usage was kept from an earlier, smaller capture, which makes `usage_complete` and `cost_complete` false. `dot login <provider> --check` prints one `provider: ready`, `login needed`, or `unknown (...)` line per provider and exits 1 unless every one is ready, without opening a login flow.

## Session archive

`~/.agents/sessions/v3` keeps one private bundle per agent session, `<agent>/<session_id>.jsonl`: a manifest line, a usage line, then the normalized transcript records. Sync writes parser 15 and reads every earlier released parser; an earlier parser's session has the status `legacy` until sync recaptures its source, and retired agents (Codex, Grok) keep theirs. Sync rewrites older schema 3 bundles in place without changing their content.

Sync publishes each bundle atomically and never replaces it with fewer records, a shorter matching message, an unavailable usage measurement or known cost, nor after a competing capture replaced it: such a session counts as `retained` and is retried on the next sync, and `retained == retained_current_transcripts` proves no transcript text was lost. Malformed JSONL and failed usage extraction count as `failed`, never replace an archived measurement, and retry on the next sync. Missing measurements remain unavailable; explicit zero counters are known zero.

Subagent transcripts (Claude subagents, Codex subagent threads) are sidechains of their parent session (`sidechain`, `parent_session_id`). Claude user entries flagged `isMeta` carry `"meta": true`, omitted when false; older captures lack the flag, so its absence does not prove a turn was user-authored. Earlier stores such as `sessions/v2` are never read or modified (remove them by hand), so a home with only an earlier store reads as empty until sync starts a v3 store. Unsupported bundles fail queries and their capture without being replaced, and an unexpandable `~user` project path is a usage error. [Session compatibility](https://github.com/fmind/dot/blob/main/.agents/skills/dot-development/references/session-compatibility.md) owns bundle schemas, parser history, and replacement mechanics; [agent usage](agent-usage.md#provider-measurement) owns provider usage measurement.
