# Dot Contracts

Configuration precedence is explicit `--config`, then `DOT_CONFIG_PATH`, then `~/.config/dot.yaml`. A missing default uses built-in defaults; an explicit missing file fails. Workstation policy lives under `auth`, `cache`, and `prune`; `dot config show` exposes the complete defaults. Scope lists replace defaults; native tools own credentials. Configuration uses `schema_version: 3` and positive finite numeric seconds in `timeout_seconds`, and `probe_timeout_seconds`. Unknown keys are rejected. Help and config repair commands remain available with malformed configuration; chezmoi-managed edits go through their source, including paths with symlinks or `..`.

Requested data goes to stdout; progress and errors go to stderr. Exit codes are 0 for success, 1 for an operational failure or incomplete result, 2 for usage errors (including unknown agent names), and 130 for interruption. Repository, diagnostic, context, and agent JSON reports have a versioned `schema` envelope; `dot orphan --json` returns an array of target records; failed operations never become an empty success. Notification hooks do not load unrelated configuration; they always exit 0 and report a failure as one stderr line.

The active `sessions/v3` store keeps one private bundle per agent session, `<agent>/<session_id>.jsonl`: a manifest line (schema 3) with provenance, counts, source signature, and usage, then the normalized records. Sync serializes writers with an owner-only `.write.lock`, checks that no competing capture replaced the observed generation, and publishes the whole file atomically. It retains the archived copy when records disappear, a matching message shrinks, or a provider token measurement or known cost becomes unavailable. Sources that change during parsing fail without publication and retry. Malformed JSONL and usage extraction failures report errors without replacing existing captures; a first capture keeps available transcript text without usage and retries. Missing measurements remain unavailable; explicit zero counters stay distinct from unknown usage, and independently reported cost remains available without claiming complete token pricing. Sync writes parser 8 and reads parser 3, 4, 5, 6, 7, and 8 bundles; earlier parsers have the session status `legacy` until sync recaptures their sources. Usage accounting separately flags parsers 3 through 6, plus parser 7 for Grok, as legacy; a newer parser alone does not invalidate other harnesses' parser 7 measurements. Parser 7 adds usage-presence accounting; an unchanged source can repair an older fabricated zero during recapture only when actual tokens and known cost are preserved. Parser 8 preserves Grok aggregate costs independently of per-model cost details and rejects explicitly incomplete usage ledgers. Parser 7 accounting remains accepted for other harnesses, including explicitly measured zero usage. Previously archived measurements remain retained when an incomplete source cannot safely replace them; sync reports that failure instead of erasing evidence. Legacy zero-token measurements remain unpriced when the old archive cannot prove that counters were observed; recognized Claude synthetic responses stay known zero. Recorded cost remains independent. Claude user text blocks and strict provider metric validation remain supported. A store that exists only as `sessions/v2` requires migration with Dot 7.0.4 and is never modified; earlier stores and standalone usage files are never read. Unsupported bundles fail queries and their capture without replacing them; sync can still capture other sessions.
