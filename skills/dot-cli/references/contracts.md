# Dot Contracts

Configuration precedence is explicit `--config`, then `DOT_CONFIG_PATH`, then `~/.config/dot.yaml`. A missing default uses built-in defaults; an explicit missing file fails. Workstation policy lives under `auth`, `cache`, and `prune`; `dot config show` exposes the complete defaults. Scope lists replace defaults, so override only the lists you change; native tools own credentials. Configuration uses `schema_version: 3`; timeouts, concurrency, and secret permissions are fixed in code. Unknown keys, including removed settings, fail with their key path; delete them with `dot config edit`. Help and config repair commands remain available with malformed configuration.

Requested data goes to stdout; progress, prompts, and errors go to stderr. Exit codes are 0 for success, 1 for an operational failure or incomplete result, 2 for usage errors (including unknown agent names), and 130 for interruption. Interruption stops launched subprocesses, including cancellation during startup. Every JSON report has a versioned `schema` envelope; failed operations never become an empty success. `orphan` and `secret` never read configuration; notification hooks read only `agent.notify` and fall back to its defaults, with one stderr line, when configuration is missing or invalid. Hooks always exit 0 and report a failure as one stderr line. Durations such as `7d` and `24h` work across date-filtered commands; zero-length durations such as `0d` exit 2; [daily workflows](daily-workflows.md) owns date boundaries.

## JSON selectors

Check the exit status: a failure before report construction may produce no JSON, and warnings stay on stderr. JSON is indented on a terminal and compact (no whitespace) when piped; parse it rather than matching text.

Diagnostics use the `dot.diagnostics/v1` envelope; agent doctor details carry `agent`, `hooks`, `source`, `last_sync`, `sync_failures`, `sync_retained`, `archive`, `sessions`, `healthy`, `next`, `discovery` (`ok`, or `broken:` with `persona` or `skills` when the deployed host files miss the shared persona or skills catalog), and `note` (an advisory that never affects `healthy`, such as the caller's environment lacking `OPENCODE_DISABLE_CLAUDE_CODE_SKILLS=1`, so an OpenCode launched from it loads the catalog twice). Native cache/provider output keeps its native format. Stats rows count model `requests` (`null` once agy or Grok contributes, since their counters track prompts or completed turns); `retained_usage_sessions` counts sessions whose usage was kept from an earlier, smaller capture, which makes `usage_complete` and `cost_complete` false. `dot login <provider> --check` prints one `provider: ready`, `login needed`, or `unknown (...)` line per provider and exits 1 unless every one is ready, without opening a login flow.

## Session archive

The active `sessions/v3` store keeps one private bundle per agent session, `<agent>/<session_id>.jsonl`, and an owner-only `.write.lock` that serializes writers: schema 4 writes a manifest line with provenance, counts, source signature, and the usage span (`usage_first_timestamp`, `usage_last_timestamp`; empty when unknown), then a usage line (the usage record or `null`), then the normalized LF-only JSONL records. Schema 3 bundles embed usage in the manifest line and start records on line 2; they stay readable, and every sync except `--dry-run` and `--session` rewrites them as schema 4 without changing their content. Metadata reads decode only the manifest line, and windowed statistics skip sessions whose whole family (a session and its sidechains) was measured outside the window.

Sync publishes each bundle atomically and never replaces it with fewer records, a shorter matching message, or an unavailable usage measurement or known cost, nor after a competing capture replaced it since parsing began. Such a session counts as `retained` (a transcript that does not shrink still publishes with the archived usage) and is retried on the next sync. Malformed JSONL and failed usage extraction count as `failed` and never replace an archived measurement, though a transcript that does not shrink still publishes; a file source that keeps changing during parsing fails without publication. Failures retry on the next sync. Sync JSON also reports `parser_version` and `dry_run`; its `retained_current_transcripts` counts retained sessions whose archived bundle is a complete current-parser copy of exactly the complete source records (only usage was kept), so `retained == retained_current_transcripts` proves no transcript text was lost. Missing measurements remain unavailable; explicit zero counters and recognized Claude synthetic responses are known zero, and independently reported cost remains available without claiming complete token pricing. [Session compatibility](https://github.com/fmind/dot/blob/main/.agents/skills/dot-development/references/session-compatibility.md) owns the replacement, generation-check, and database-checkpoint mechanics.

Sync writes parser 14 and reads parser 3 through 14 bundles; earlier parsers have the session status `legacy` until sync recaptures their sources; retired agents (Codex, Grok) keep theirs. Parser 13 reports Antigravity's unverified model identity as `unknown`. Usage accounting separately flags parsers 3 through 6, plus parser 7 for Grok, as legacy, judged by the parser that measured the usage; a legacy zero is unpriced because those parsers conflated absent counters with explicit zero. Parser 10 treats Claude's `cost-state.hasUnknownModelCost` as unknown cost, marks Claude subagent transcripts and Codex subagent threads as sidechains of their parent session (`sidechain`, `parent_session_id`), and skips Claude workflow journals; the [usage queries guide](../../agent-usage/references/queries.md) owns provider usage measurement (Grok incomplete ledgers, Claude 1-hour cache writes, Codex per-response usage, OpenCode steps). Deeply nested JSON is malformed input, and an unexpandable `~user` project path is a usage error.

Parser 14 preserves Claude user entries whose raw `isMeta` is exactly `true` as `"meta": true` on the normalized transcript record. `meta` is an optional boolean, defaults to false when absent, and is omitted when false; the v3 store layout is unchanged. Dot retains these entries and their text so consumers can choose whether to skip injected turns. Missing flags in older captures do not prove a turn was user-authored; sync recaptures available sources, while deleted sources remain readable without this evidence.

Earlier stores such as `sessions/v2` (remove them by hand) and standalone usage files are never read or modified, so a home with only an earlier store reads as an empty archive until sync starts a v3 store. Unsupported bundles fail queries and their capture without replacing them; sync can still capture other sessions.
