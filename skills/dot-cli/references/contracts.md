# Dot Contracts

Configuration precedence is explicit `--config`, then `DOT_CONFIG_PATH`, then `~/.config/dot.yaml`. A missing default uses built-in defaults; an explicit missing file fails. Workstation policy lives under `auth`, `cache`, and `prune`; `dot config show` exposes the complete defaults. Scope lists replace defaults, so override only the lists you change; native tools own credentials. Configuration uses `schema_version: 3` and positive finite numeric seconds in `timeout_seconds` and `probe_timeout_seconds`. Unknown keys are rejected, so delete `auth.github.host` (removed after 9.0.3; GitHub login always targets github.com) with `dot config edit`. Help and config repair commands remain available with malformed configuration.

Requested data goes to stdout; progress, prompts, and errors go to stderr. Exit codes are 0 for success, 1 for an operational failure or incomplete result, 2 for usage errors (including unknown agent names), and 130 for interruption. Every JSON report has a versioned `schema` envelope; failed operations never become an empty success. Notification hooks, `orphan`, and `secret` never read configuration; hooks always exit 0 and report a failure as one stderr line. Durations such as `7d` and `24h` work across date-filtered commands; zero-length durations such as `0d` exit 2; [daily workflows](daily-workflows.md) owns date boundaries.

## JSON selectors

Check the exit status: a failure before report construction may produce no JSON, and warnings stay on stderr.

| `dot cache --json`                  | `dot.cache/v1`                | `.providers[]` with `name`, `command`, and native `report`, `error`, or `skipped` (not installed, under `all`); `--dry-run` lists commands only. |

| `dot agent stats --json`            | `dot.agent.stats/v3`          | `.prompts` (`null` when token-only) and `.usage[]` (empty when prompt-only).                                                                     |

Diagnostics use the `dot.diagnostics/v1` envelope; agent doctor details carry `agent`, `hooks`, `source`, `last_sync`, `sync_failures`, `sync_retained`, `archive`, `sessions`, `healthy`, `next`, `discovery` (`ok`, or `broken:` with `persona`, `skills`, or `agents` when the deployed host files miss the shared persona, skills catalog, or compiled subagents), and `note` (an advisory that never affects `healthy`, such as the caller's environment lacking `OPENCODE_DISABLE_CLAUDE_CODE_SKILLS=1`, so an OpenCode launched from it loads the catalog twice). Native cache/provider output keeps its native format. Stats rows count model `requests` (`null` once agy or Grok contributes, since their counters track prompts or completed turns); `retained_usage_sessions` counts sessions whose usage was kept from an earlier, smaller capture, which makes `usage_complete` and `cost_complete` false. `dot login <provider> --check` prints one `provider: ready`, `login needed`, or `unknown (...)` line per provider and exits 1 unless every one is ready, without opening a login flow.

## Session archive

The active `sessions/v3` store keeps one private bundle per agent session, `<agent>/<session_id>.jsonl`: a manifest line (schema 3) with provenance, counts, source signature, and usage, then the normalized LF-only JSONL records. Sync serializes writers with an owner-only `.write.lock` and publishes the whole file atomically. It retains the archived copy when records disappear, a matching message shrinks, or a competing capture replaced the observed generation since parsing began. When only a provider token measurement or known cost would become unavailable, it publishes a transcript that does not shrink with the archived usage, records the measuring parser in `usage_parser_version`, counts the session as retained, and retries it on the next sync. Sync JSON also reports `parser_version` and `dry_run`; its `retained_current_transcripts` counts retained sessions whose archived bundle is a complete current-parser copy of exactly the complete source records (only usage was kept), so `retained == retained_current_transcripts` proves no transcript text was lost. A source that changes during parsing is parsed once more; if it changes again, it fails without publication and retries on the next sync. Malformed JSONL and usage extraction failures count as failures and never replace an archived measurement; the transcript still publishes under the same non-shrink rules, with the archived usage or, for a first capture, without usage, and retries. Missing measurements remain unavailable; explicit zero counters and recognized Claude synthetic responses are known zero, and independently reported cost remains available without claiming complete token pricing.

Sync writes parser 12 and reads parser 3 through 12 bundles; earlier parsers have the session status `legacy` until sync recaptures their sources. Usage accounting separately flags parsers 3 through 6, plus parser 7 for Grok, as legacy, judged by the parser that measured the usage; a legacy zero is unpriced because those parsers conflated absent counters with explicit zero. Parser 10 treats Claude's `cost-state.hasUnknownModelCost` as unknown cost, marks Claude subagent transcripts and Codex subagent threads as sidechains of their parent session (`sidechain`, `parent_session_id`), and skips Claude workflow journals; the [usage queries guide](../../agent-usage/references/queries.md) owns per-parser usage measurement (Grok incomplete ledgers, Claude 1-hour cache writes, Codex per-response usage, OpenCode steps). Deeply nested JSON is malformed input, and an unexpandable `~user` project path is a usage error.

Earlier stores (remove them by hand) and standalone usage files are never read or modified. Dot 7.0.4 was the last release to migrate `sessions/v2`, so a v2-only home reads as an empty archive until sync starts a v3 store. Unsupported bundles fail queries and their capture without replacing them; sync can still capture other sessions.
