# Python Profiling

Locate a measured slowdown with a representative, bounded workload run through `uv`; [benchmark](benchmark.md) owns uninstrumented before/after comparisons. Add a profiler as a development dependency only for a concrete need; keep captures private (they reveal paths and workload details) and read only trusted profile files.

- **Separate waiting from computation first**: compare elapsed and CPU time for the same work before choosing a tool.
- **Default to Pyinstrument for time**: `uv run pyinstrument -r html -o profile.html workload.py` (or `-m package.module`) gives sampled elapsed-time trees, waits included; choose async attribution deliberately.
- **Use the stdlib sampler on Python 3.15+**: `uv run python -m profiling.sampling run --flamegraph -o profile.html workload.py` needs no dependency; `--mode cpu` drops waits, `-a` samples all threads, `--async-aware` follows asyncio tasks, `--subprocesses` follows workers, and `--diff-flamegraph base.bin` compares against a `--binary -o base.bin` capture. Before 3.15, `python -m cProfile` remains the zero-install fallback, but its timings are biased and miss worker threads.
- **Default to Memray for memory**: `uv run memray run -o capture.bin workload.py`, then `uv run memray stats capture.bin` and `uv run memray flamegraph -o memory.html capture.bin`; add `--native` at capture time when extension allocations matter, and pass `--confidential-files=all` to `memray flamegraph` before sharing a report. Allocation volume is not a leak, and RSS includes allocator arenas and mapped memory; if RSS grows without tracked allocation growth, look at native buffers, mapped files, and child processes.
- **Launch hung processes under a sampler**: attaching with `py-spy dump --pid`, `profiling.sampling attach`, `python -m pdb -p`, `python -m asyncio pstree`, or `sys.remote_exec` (3.14+) needs ptrace, which Yama `ptrace_scope` 1 denies without elevation (out of scope). Launch instead with `uv run --with py-spy py-spy record -o profile.svg --subprocesses -- python workload.py`, or pre-arm `faulthandler.register(signal.SIGUSR1)` to dump stacks on a signal. py-spy 0.4.2 rejects Python 3.15 targets (`Unsupported version of Python`); launch those under `profiling.sampling run` instead.
- **Inspect state without a TTY**: `uv run --locked pytest -x -l --lf <path>` shows the failing locals. For a script, `uv run python -m pdb -c continue -c 'p <expr>' -c quit script.py < /dev/null` prints post-mortem values; that run exits 0 even when the script raised, so take the verdict from a plain run.
- **Change one cause, then remeasure**: rerun the same uninstrumented workload plus correctness tests, and remove temporary instrumentation unless it has an owner.
