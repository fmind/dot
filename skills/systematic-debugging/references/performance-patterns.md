# Backend Performance Patterns

Fix a backend slowdown that [Python profiling](python-profiling.md) or a query log has already located; prove each fix with the [benchmark](benchmark.md) keep-or-revert step.

- **Count queries per request first**: a request whose query count grows with its result size is an N+1. Load relations eagerly (SQLAlchemy `selectinload()`, Django `select_related()` for single-valued and `prefetch_related()` for many-valued relations), and lock the count in a test: Django `assertNumQueries`, or SQLAlchemy `raiseload("*")` so a forgotten lazy load fails. Bound every list with a page size.
- **Read the plan before and after an index**: run `EXPLAIN (ANALYZE, BUFFERS)` on the exact slow query. A sequential scan where you expected an index means no usable index; estimated rows off by 10× or more means stale statistics (`ANALYZE`); a sort above the scan means the index misses the `ORDER BY`. Index the query's shape (equality columns, then the range or sort column) or the expression (`lower(email)`). Revert an index that leaves the plan unchanged, because every index slows writes.
- **Size connection pools against the database limit**: when every endpoint slows at once and time goes to waiting for a connection, the pool is exhausted. Keep one pool per process and `max_instances × (pool_size + max_overflow)` below the database's `max_connections` minus admin headroom; SQLAlchemy defaults to 5 + 10 per process. Set a short checkout timeout so requests fail fast. On autoscaled services such as Cloud Run, add a connection pooler (PgBouncer or the provider's managed pooler) instead of raising pool sizes.
- **Share state that must hold across instances**: in-memory caches and rate limiters become per-instance, so a limit of `N` turns into `N × instances` or never fires after scale-to-zero. Back them with a shared store when instances must agree.
- **Key caches on every input**: include tenant, viewer, locale, and feature flags in the cache key; a key without the viewer serves one user's data to another. State the staleness window, coalesce concurrent misses on hot keys, and never cache values whose staleness is a correctness bug (permissions, balances, stock at checkout).
