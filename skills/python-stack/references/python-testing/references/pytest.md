# pytest Mechanics

Use the project's existing pytest configuration and canonical test task; [python-stack](../../foundation/GUIDE.md) owns the shared configuration baseline. For test-only maintenance, follow this guide without claiming a test-first implementation cycle.

1. **Check collection, then focus**: inspect collection with `uv run pytest --collect-only -q <tests-path>` when discovery is uncertain, then run a focused case with `uv run pytest -q <path>::<test-name>`. Exit code 5 means no tests were collected. After a failing run, iterate with `--lf` (last failures) or `--sw` (stepwise), then rerun the relevant suite once.
1. **Keep output quiet but complete**: prefer `-q` for routine runs; keep counts, warnings, failure traces, and required coverage gates. Add `-v` or capture changes only for a concrete diagnostic need. Use [mise output conventions](../../../../mise/references/task-conventions.md#concise-output) to move per-file coverage into an on-demand report; do not disable coverage or skip required tests to shorten output.
1. **Parametrize partitions; scope `pytest.raises` tightly**: parametrize meaningful input partitions. Keep only the expected failing operation inside `pytest.raises(..., match=...)` so setup errors cannot satisfy the assertion.
1. **Reset state per Hypothesis example**: for Hypothesis, follow [property tests](property-tests.md). A function-scoped fixture is not recreated for every generated example; reset mutable state per example and preserve health checks.
1. **Run the suite and inspect skips**: run the relevant suite and native gate. Inspect warnings, skips, and collection counts; unexpected deselection or skips leave behavior unverified. Keep custom markers registered and configuration strict with `strict = true` under `[tool.pytest]`; move legacy `[tool.pytest.ini_options]` keys into that table, because pytest rejects both tables together (exit 4).

pytest runs no `async def` test on its own. When the project already depends on `anyio` (Litestar, Starlette, FastAPI, HTTPX), use its bundled pytest plugin: mark async tests `@pytest.mark.anyio`, as the Litestar starter does, or set `anyio_mode = "auto"`; otherwise add `pytest-asyncio` with `asyncio_mode = "auto"`, whose default `strict` mode requires `@pytest.mark.asyncio` on every async test. Under `filterwarnings = ["error"]`, a plugin warning at startup aborts the whole run (exit 3), and pytest 9.2 raises more of them: keep AnyIO at 4.15+ wherever it is installed, even transitively; set `asyncio_default_fixture_loop_scope = "function"` wherever pytest-asyncio is installed, even unused; and never enable both auto modes.

Add `pytest-xdist` and run `-n auto` only when serial wall time exceeds roughly ten seconds and is dominated by waiting on subprocesses, fsync, or the network; worker startup makes a small fast suite several times slower. Keep `-n` out of `addopts` so focused runs stay serial: `-n auto --pdb` silently falls back to one process, an explicit `-n <count> --pdb` is a usage error, and `-x` stops only after in-flight tests on other workers finish. A session-scoped fixture is built once per worker, so tests sharing a container, port, path, or module state must be fixed rather than pinned to one worker. Measure coverage with `pytest --cov`; `coverage run -m pytest -n ...` silently reports 0%. pytest-cov 7 dropped subprocess measurement: keep `[tool.coverage.run] patch = ["subprocess"]` so `python -m <package>` tests count instead of lowering the gate or duplicating them in-process. The patch writes parallel data files, which pytest-cov combines; run `coverage combine` before reporting a bare `coverage run`.

Keep the plugin set small: `pytest-cov` for coverage, `pytest-watcher` for the watch loop, and the foundation's two guards. `pytest-socket` keeps the offline suite offline: a connect beyond loopback fails naming the host. Move live calls behind `-m integration`, whose task passes `--force-enable-socket`, instead of widening `--allow-hosts`; the plugin blocks connects, not DNS lookups or subprocess traffic, and `--disable-socket` would also block the loopback binds starter tests use. `pytest-timeout` (`timeout = "60"`, quoted) fails only the hung test and keeps the summary; the integration task raises it to 600 because session setup, such as a first image pull, counts against the first test. Add no others by reflex: pytest 9 ships subtests natively and ignores an installed `pytest-subtests`, and `monkeypatch` with `unittest.mock` usually covers mocking needs. Inject the clock where you can; when code reads the wall clock directly, use `time-machine` (`@pytest.mark.time_machine(<destination>)`) rather than freezegun: since 3.0 it leaves `time.monotonic` alone, so asyncio timeouts keep working. pytest 9's `faulthandler_exit_on_timeout = true` aborts the whole run without fixture teardown or a summary; keep it a last resort behind `pytest-timeout`.

Add `inline-snapshot` when hand-written expected values for large structured outputs (rendered payloads, parsed documents, CLI JSON) would be tedious or drift. Write `assert result == snapshot()`, run `pytest --inline-snapshot=create` to fill empty snapshots and `--inline-snapshot=fix` to rewrite mismatches, then review the source diff as the assertion change. The writing run still reports errors; rerun plainly to confirm green, and never pass either flag in a gate. Both flags refuse to run under `pytest-xdist`, so update serially. Set `[tool.inline-snapshot] format-command = "ruff format --stdin-filename {filename}"` so written values match the formatter. Keep hand-written assertions for small values and contracts a reader should see stated. Replace volatile values inside a snapshot with `dirty-equals` matchers (`IsUUID()`, `IsDatetime()`, `IsStr(regex=...)`); `--inline-snapshot=fix` keeps them and rewrites only the changed literals.
