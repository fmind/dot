# Headless Remote Control

Use the CLI daemon without installing the desktop app. Read [Remote Control](https://antigravity.google/docs/remote-control/) before changing its persistent OS service. `agy remote-control status` is read-only; `start` registers/restarts and `stop` unregisters it. Restart only when no remote task is running; verify the browser project picker separately.

For one terminal session, `agy --remote-control` or `/remote-control` opens a tunnel that lives only as long as that process and prints a link to the conversation; `/remote-control off` closes it. The daemon is one per machine: a systemd user service `antigravity-cli-daemon` on Linux (`journalctl --user -u antigravity-cli-daemon -n 50`), or an unsupervised background process when no systemd user manager exists. `start --name <name>` sets `cliRemoteControlHostname`; `remoteControlHostname` belongs to the desktop app. The browser Settings modal syncs supported CLI settings (permissions, queued messages, AI credits, telemetry, and artifact review) back to `settings.json`, while "Always allow" rules approved in the browser save to the shared `config.json`. Remote Control requires a Google account or organization with Remote Control enabled and is unsupported under `AGY_ADC_AUTH` (`--remote-control` exits with an error and `/remote-control` is hidden).

The daemon reads `~/.gemini/config/config.json` only at start: run `agy remote-control start` after applying changes. agy runs agent commands in `bash`, not `$SHELL`, so on Linux a chezmoi drop-in starts the daemon through non-interactive fish: remote sessions get the terminal environment (`env.fish`, mise shims first on `PATH`) plus `CLOUDSDK_CORE_DISABLE_PROMPTS=1` and `GH_PROMPT_DISABLED=1`. Any agy launch, including background jobs at any hour, can update `~/.local/bin/agy` while the daemon keeps the replaced binary (`ls -l /proc/<MainPID>/exe` shows `(deleted)`). A restart ends any remote task in progress, so `antigravity-cli-daemon-update.timer` restarts the daemon at 04:30 only when it runs an outdated binary; agy records no reliable busy signal for the daemon, so the check cannot wait for idle. Avoid leaving long remote tasks running across 04:30, or restart by hand after an update. Apply reloads systemd when these units change but never restarts the daemon, so restart it yourself when no remote task is running.

The browser project picker reads the local registry in `~/.gemini/config/projects/`. `dot trust`, which every apply runs for `all` workspaces and the chezmoi source, adds each trusted repository missing from it, except those matching `trust.agy_projects_exclude` in `~/.config/dot.yaml` (default `~/fmind/agent-*`, `~/fmind/fgraph`, and `~/fmind/mcp-context-benchmark`; absolute or `~/` globs over the resolved repository path). Preview with `dot trust all --dry-run`. Like trust, it only adds: entries agy or you created stay, so delete a removed checkout's `<id>.json` yourself; entries without folders, such as the native default project, are ignored. New entries use agy's own `local-<sha256>` IDs and atomic owner-only writes; malformed registry JSON stops `dot trust` before any file changes. This registers projects, not semantic code indexes.

The browser lists each project's conversations from agy's summary index, which agy rebuilds from each conversation's own file and re-syncs from its summary caches (`jetbox_summaries_proto.pb`, `agyhub_summaries_proto.pb`) on every start. Editing the index cannot move a conversation to another project, and deleting conversation files outside agy leaves an entry that agy keeps listing: delete conversations inside agy (`F4` in `/resume`, or Delete in the app's conversation menu). Background runs belong in their own folderless project (a `{"id", "name", "projectResources": {}}` entry passed as `--project ID`; an unknown project silently falls back to the default CLI Project), as the brain's assistants use `Brain assistants`.
