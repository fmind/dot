# Session Compatibility

Read this before changing discovery, parser output, replacement rules, or storage. [store.py](../../../../dot/src/fmind_dot/archive/store.py), [sync.py](../../../../dot/src/fmind_dot/archive/sync.py), [parsers.py](../../../../dot/src/fmind_dot/archive/parsers.py), and [query.py](../../../../dot/src/fmind_dot/archive/query.py) define current behavior; do not treat a remembered version number as current.

## Change boundary

1. Identify whether the change affects source discovery, normalized transcript bytes, usage extraction, the bundle manifest, or queries. Check callers in `agent.py` and the matching parser/store/query tests.
1. For changed normalized output from the same source, bump `SESSION_PARSER_VERSION`: sync reparses every source whose stored parser differs, subject to the retention rules below. Evaluate `SESSION_SCHEMA_VERSION` and `SESSION_STORE_VERSION` separately when the bundle structure or layout changes; a new store needs a migration from the previous one that never modifies the old store.
1. Preserve the replacement rules: one bundle per agent and session; never replace with fewer records or shorten an existing message matched by role and timestamp in source order. Malformed JSONL or failed usage extraction never replaces an archived measurement: the transcript still publishes under these non-shrink rules with the archived usage (or without usage for a new session), and sync retries the source. Missing provider measurements remain unavailable, while explicit zero counters and Claude's `<synthetic>` responses remain known zero. Preserve independently reported cost without claiming a token measurement. Never replace measured usage or known cost with an unavailable measurement; a parser upgrade may remove an earlier false zero only when the source fingerprint is unchanged and no tokens or known cost would be lost. When only the measurement would be lost and records do not shrink, publish the transcript with the archived usage, record the parser that measured it in `usage_parser_version` (legacy accounting follows it), clear the source signature so sync retries, and report the session as retained.
1. Reject sources that change while being parsed, and compare the observed bundle generation under the publication lock before replacing it. File sources use size/mtime signatures; Codex discovery also walks the sibling `archived_sessions/`, where the live `sessions/` copy wins a duplicate id. Adapters with `external_cwd` (agy, whose CWD comes from `conversation_summaries.db`) append `;cwd=<path>` to the signature and fold the CWD into the fingerprint: a newly resolved workspace recaptures the session, and missing metadata keeps the stored `;cwd=` signature. SQLite sources include the WAL and share a database checkpoint; publish that checkpoint only after a complete, unfiltered pass with no failures, retained bundles, or source changes.
1. Keep owner-only permissions, locked read/compare/write publication, atomic file replacement, and safe path components for agent and session identities. Keep private transcript content out of fixtures and diagnostic output; use synthetic records.
1. Test repeated sync, truncated chunks, competing equal-count captures, absent and failed usage, malformed input, migration, and query selection. Verify that unsupported bundles fail queries and their capture without replacing retained data; other sessions can still synchronize.

## Useful evidence

- [Parser tests](../../../../dot/tests/test_agent_parsers.py): source snapshots, malformed records, supported formats, and usage metrics.
- [Workflow tests](../../../../dot/tests/test_agent_workflows.py): database checkpoints, filtered sync, failed captures, and changes during a pass.
- [Storage tests](../../../../dot/tests/test_session_store.py): bundle layout, private permissions, replacement rules, and corruption.
- [Transaction tests](../../../../dot/tests/test_archive_transaction.py): incremental sync, usage retention, and the retired v2 store refusal.
- [Query tests](../../../../dot/tests/test_session_query.py): status, filters, and archive retrieval.
- [OpenCode tests](../../../../dot/tests/test_opencode_archive.py): database capture into the shared archive without treating tool output as user input.

The active store is `sessions/v3`: each `<agent>/<session_id>.jsonl` holds a manifest line (schema 3, including `usage` and the source signature) followed by normalized records. Schema 3 readers ignore unknown manifest and usage keys, so optional fields with neutral defaults (`sidechain`, `parent_session_id`, `usage_parser_version`, `cache_write_1h_tokens`) need no schema bump; a changed meaning does. A sidechain is a subagent transcript of its parent session: statistics count its tokens with the parent and never as another session, prompt, or cost. `SESSION_PARSER_VERSION` and `READABLE_PARSER_VERSIONS` in `store.py` own the current and readable parser versions, documented in [contracts](../../../../skills/dot-cli/references/contracts.md). Earlier parsers remain readable and have the session status `legacy` until sync recaptures their sources. Usage accounting independently flags parsers 3 through 6, plus parser 7 for Grok, as legacy, judged by the parser that measured retained usage; parser 7 measurements for other harnesses remain accepted. Legacy zero-token measurements remain unpriced unless they are recognized Claude synthetic responses; their recorded cost is independent. A retained archive cannot establish whether the original counters were absent, so unavailable source evidence remains unknown instead of being reconstructed or migrated. The v2 migration shipped through Dot 7.0.4; a store that exists only as `sessions/v2` now fails closed with that release named, and `sessions/v2` stays untouched for the owner to remove. Provider-source pruning is outside Dot.
