# Session Compatibility

Read this before changing discovery, parser output, replacement rules, or storage. [store.py](../../../../dot/src/fmind_dot/archive/store.py), [sync.py](../../../../dot/src/fmind_dot/archive/sync.py), [parsers.py](../../../../dot/src/fmind_dot/archive/parsers.py), and [query.py](../../../../dot/src/fmind_dot/archive/query.py) define current behavior; do not treat a remembered version number as current.

## Change boundary

1. **Classify the affected layer**: identify whether the change affects source discovery, normalized transcript bytes, usage extraction, the bundle manifest, or queries. Check callers in `agent.py` and the matching parser/store/query tests.
1. **Bump the matching version**: for changed normalized output from the same source, bump `SESSION_PARSER_VERSION`: sync reparses every source whose stored parser differs, subject to the retention rules below. Skip the bump when the change only drops records, since retention would keep every older bundle and retry it on each sync; the change then reaches new and grown captures only (agy's `truncated_fields` skip). Evaluate `SESSION_SCHEMA_VERSION` and `SESSION_STORE_VERSION` separately when the bundle structure or layout changes; a new store needs a migration from the previous one that never modifies the old store.
1. **Preserve the replacement rules**: one bundle per agent and session; never replace with fewer records or shorten an existing message matched by role and timestamp in source order. Never replace measured usage or known cost with an unavailable measurement; an archived zero stays until the source is measured again. A transcript that does not shrink still publishes with the archived usage (or none for a new session) and sync retries the source: malformed JSONL or failed extraction reports an error, while a measurement that merely became unavailable records its measuring parser in `usage_parser_version` (legacy accounting follows it), clears the source signature, and reports the session as retained. Missing provider measurements remain unavailable, while explicit zero counters and Claude's `<synthetic>` responses remain known zero; preserve independently reported cost without claiming a token measurement.
1. **Reject sources changed during parsing**: compare the observed bundle generation under the publication lock before replacing it; a mismatch retains the stored bundle. File sources use size/mtime signatures, and a source that changes during parsing is parsed once more, then fails without publication if it changes again. Adapters with `external_cwd` (agy, whose CWD comes from `conversation_summaries.db`) append `;cwd=<path>` to the signature and fold the CWD into the fingerprint: a newly resolved workspace recaptures the session, and missing metadata keeps the stored `;cwd=` signature. SQLite sources parse each session inside one read snapshot, so concurrent writes never fail it; they include the WAL and share a database checkpoint; publish that checkpoint only after a complete, unfiltered pass with no failures, retained bundles, or source changes.
1. **Keep the archive private and atomic**: keep owner-only permissions, locked read/compare/write publication, atomic file replacement, and safe path components for agent and session identities. An unreadable existing bundle must never be treated as absent; check it before repairing its agent directory permissions or publishing. Keep private transcript content out of fixtures and diagnostic output; use synthetic records.
1. **Test failure and retention paths**: test repeated sync, truncated chunks, competing equal-count captures, absent and failed usage, malformed input, migration, and query selection. Verify that unsupported bundles fail queries and their capture without replacing retained data; other sessions can still synchronize.

## Store layout and parser history

- **Bundle layout**: the `sessions/v3` store keeps `<agent>/<session_id>.jsonl` and an owner-only `.write.lock` that serializes writers. Schema 4 writes a manifest line (provenance, counts, source signature, and the usage span `usage_first_timestamp`/`usage_last_timestamp`, empty when unknown), then a usage line (the record or `null`), then LF-only normalized JSONL records. Schema 3 bundles embed usage in the manifest and start records on line 2; every sync except `--dry-run` and `--session` rewrites them as schema 4 without changing their content.
- **Read paths**: metadata reads decode only the manifest line, and windowed statistics skip sessions whose whole family (a session and its sidechains) was measured outside the window. Deeply nested JSON is malformed input, and so is a source JSONL record whose escapes decode to a lone UTF-16 surrogate, which UTF-8 cannot store: the session archives as `partial` instead of failing.
- **Parser history**: parser 10 marks Claude subagent transcripts and Codex subagent threads as sidechains of their parent (`sidechain`, `parent_session_id`) and skips Claude workflow journals; parser 13 reports Antigravity's unverified model identity as `unknown`; parser 14 preserves Claude user entries whose raw `isMeta` is exactly `true` as `"meta": true` (an optional boolean, omitted when false, with the v3 layout unchanged), keeping their text so consumers choose whether to skip injected turns; parser 15 reads Antigravity's provider-reported request counters instead of estimating tokens. Sync recaptures available sources after a bump, while deleted sources stay readable without the newer evidence. [Agent usage](../../../../skills/dot-cli/references/agent-usage.md#provider-measurement) owns the accounting consequences (legacy flags, pricing).

- [Workflow tests](../../../../dot/tests/test_agent_workflows.py): database checkpoints, filtered sync, failed captures, and changes during a pass.
- [Storage tests](../../../../dot/tests/test_session_store.py): bundle layout, private permissions, replacement rules, and corruption.
- [Transaction tests](../../../../dot/tests/test_archive_transaction.py): incremental sync and usage retention.
- [Query tests](../../../../dot/tests/test_session_query.py): status, filters, and archive retrieval.
- [OpenCode tests](../../../../dot/tests/test_opencode_archive.py): the store is accepted only while it holds no session; 2.x and 1.x sessions are refused, never skipped.

[Contracts](../../../../skills/dot-cli/references/contracts.md#session-archive) documents the statuses and retention that users see; `SESSION_PARSER_VERSION` and `READABLE_PARSER_VERSIONS` in `store.py` own those versions. Schema 4 readers ignore unknown manifest and top-level usage keys, so optional fields with neutral defaults (`sidechain`, `parent_session_id`, `usage_parser_version`, `cache_write_1h_tokens`) need no schema bump; a changed meaning or line layout does. Usage `samples` stay closed (`UsageSample` forbids extra keys), so a new per-request field needs a parser bump. A layout bump keeps the previous schema readable and upgrades it in place under the write lock (`upgrade_session_bundle`), because deleted sources can never be recaptured. Consumers outside Dot that read bundles directly (the brain's `agent-sessions` collector) must accept the new schema before a release deploys it. Preserve the [sidechain accounting](../../../../skills/dot-cli/references/agent-usage.md#commands) when changing statistics. Every released parser version stays readable, because a bundle whose source the provider deleted can never be recaptured; never drop one. Retiring a harness removes its adapter, not its archive: list it in `RETIRED_AGENTS` (`archive/usage.py`) so `--agent` still selects its bundles and sync rejects it clearly, and keep its accounting and pricing rules in `usage.py`, `pricing.py`, and `api-prices.yaml` (Codex and Grok since 2026-10-25). A retained archive cannot establish whether the original counters were absent, so unavailable source evidence remains unknown instead of being reconstructed or migrated. Provider-source pruning is outside Dot.
