# Session Compatibility

Read this before changing discovery, parser output, replacement rules, or storage. [store.py](../../../../dot/src/fmind_dot/archive/store.py), [sync.py](../../../../dot/src/fmind_dot/archive/sync.py), [parsers.py](../../../../dot/src/fmind_dot/archive/parsers.py), and [query.py](../../../../dot/src/fmind_dot/archive/query.py) define current behavior; do not treat a remembered version number as current.

## Change boundary

1. **Classify the affected layer**: identify whether the change affects source discovery, normalized transcript bytes, usage extraction, the bundle manifest, or queries. Check callers in `agent.py` and the matching parser/store/query tests.
1. **Bump the matching version**: for changed normalized output from the same source, bump `SESSION_PARSER_VERSION`: sync reparses every source whose stored parser differs, subject to the retention rules below. Evaluate `SESSION_SCHEMA_VERSION` and `SESSION_STORE_VERSION` separately when the bundle structure or layout changes; a new store needs a migration from the previous one that never modifies the old store.
1. **Preserve the replacement rules**: one bundle per agent and session; never replace with fewer records or shorten an existing message matched by role and timestamp in source order. Never replace measured usage or known cost with an unavailable measurement; an archived zero stays until the source is measured again. A transcript that does not shrink still publishes with the archived usage (or none for a new session) and sync retries the source: malformed JSONL or failed extraction reports an error, while a measurement that merely became unavailable records its measuring parser in `usage_parser_version` (legacy accounting follows it), clears the source signature, and reports the session as retained. Missing provider measurements remain unavailable, while explicit zero counters and Claude's `<synthetic>` responses remain known zero; preserve independently reported cost without claiming a token measurement.
1. **Reject sources changed during parsing**: compare the observed bundle generation under the publication lock before replacing it. File sources use size/mtime signatures; Codex discovery also walks the sibling `archived_sessions/`, where the live `sessions/` copy wins a duplicate id. Adapters with `external_cwd` (agy, whose CWD comes from `conversation_summaries.db`) append `;cwd=<path>` to the signature and fold the CWD into the fingerprint: a newly resolved workspace recaptures the session, and missing metadata keeps the stored `;cwd=` signature. SQLite sources include the WAL and share a database checkpoint; publish that checkpoint only after a complete, unfiltered pass with no failures, retained bundles, or source changes.
1. **Keep the archive private and atomic**: keep owner-only permissions, locked read/compare/write publication, atomic file replacement, and safe path components for agent and session identities. Keep private transcript content out of fixtures and diagnostic output; use synthetic records.
1. **Test failure and retention paths**: test repeated sync, truncated chunks, competing equal-count captures, absent and failed usage, malformed input, migration, and query selection. Verify that unsupported bundles fail queries and their capture without replacing retained data; other sessions can still synchronize.

## Useful evidence

- [Parser tests](../../../../dot/tests/test_agent_parsers.py): source snapshots, malformed records, supported formats, and usage metrics.
- [Workflow tests](../../../../dot/tests/test_agent_workflows.py): database checkpoints, filtered sync, failed captures, and changes during a pass.
- [Storage tests](../../../../dot/tests/test_session_store.py): bundle layout, private permissions, replacement rules, and corruption.
- [Transaction tests](../../../../dot/tests/test_archive_transaction.py): incremental sync and usage retention.
- [Query tests](../../../../dot/tests/test_session_query.py): status, filters, and archive retrieval.
- [OpenCode tests](../../../../dot/tests/test_opencode_archive.py): database capture into the shared archive without treating tool output as user input.

The active store is `sessions/v3`: each `<agent>/<session_id>.jsonl` holds a manifest line (schema 3, including `usage` and the source signature) followed by normalized records. Schema 3 readers ignore unknown manifest and usage keys, so optional fields with neutral defaults (`sidechain`, `parent_session_id`, `usage_parser_version`, `cache_write_1h_tokens`) need no schema bump; a changed meaning does. A sidechain is a subagent transcript of its parent session: statistics count its tokens with the parent and never as another session, prompt, or cost. `SESSION_PARSER_VERSION` and `READABLE_PARSER_VERSIONS` in `store.py` own the current and readable parser versions, documented in [contracts](../../../../skills/dot-cli/references/contracts.md). Earlier parsers remain readable and have the session status `legacy` until sync recaptures their sources. Every released parser version stays readable, because a bundle whose source the provider deleted can never be recaptured; never drop one. Usage accounting flags parser 7 Grok measurements as legacy, judged by the parser that measured retained usage. A retained archive cannot establish whether the original counters were absent, so unavailable source evidence remains unknown instead of being reconstructed or migrated. Older stores such as `sessions/v2` are never read; remove them by hand. Provider-source pruning is outside Dot.
